# Build a Complete "Daily Journal with Mood Tracker" Web Application

Act as a **senior frontend developer and UI/UX engineer**.

Build a complete, production-quality **Daily Journal with Mood Tracker** web application using only:

* HTML5
* CSS3
* Vanilla JavaScript (ES6+)
* Browser Local Storage as the database

Do **not** use React, Angular, Vue, Bootstrap, Tailwind, jQuery, or any backend/database.

The application should be fully functional by opening `index.html` in a browser.

---

# 1. Application Overview

Create a modern personal journaling application where users can:

1. View a dashboard/home page.
2. Add a journal entry for today.
3. Add a journal entry for any selected date.
4. Select and save their mood.
5. View all previous journal entries.
6. Search and filter journal entries.
7. Edit existing journal entries.
8. Delete journal entries.
9. View basic journaling and mood statistics.
10. Persist all journal data using browser Local Storage.

The application should feel like a combination of:

* Notion
* Google Keep
* Modern personal journal applications
* Minimal productivity dashboards

The UI should be clean, elegant, calm, modern, and distraction-free.

# 20. Local Storage Database

Use Local Storage as the application's database.

Storage key:

```text
dailyJournalEntries
```

Store data as JSON.

Example:

```javascript
[
    {
        id: "journal_1725812345678",
        date: "2026-09-08",
        title: "A Productive Day",
        content: "Today was a very productive day...",
        mood: {
            id: "happy",
            label: "Happy",
            emoji: "😊"
        },
        createdAt: "2026-09-08T10:30:00.000Z",
        updatedAt: "2026-09-08T10:30:00.000Z"
    }
]
```

Create reusable storage functions:

```javascript
getJournals()
saveJournal(journal)
updateJournal(id, updatedJournal)
deleteJournal(id)
getJournalById(id)
clearAllJournals()
```

Always safely parse Local Storage JSON.

Handle the case where Local Storage is empty.

# 34. Date Handling

Use native JavaScript Date APIs.

Display dates in human-friendly format.

Example:

```text
September 8, 2026
```

For recent entries, optionally show:

```text
Today
Yesterday
2 days ago
```

but retain the full date where useful.

Avoid external date libraries.

Be careful with timezone-related date bugs.

For date input values, use local date formatting rather than blindly using `toISOString()` because UTC conversion can shift the date.

Create a utility function such as:

```javascript
getLocalDateString()
```

that returns:

```text
YYYY-MM-DD
```
